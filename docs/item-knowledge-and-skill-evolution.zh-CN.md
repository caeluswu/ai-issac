# 道具能力扩展：局内生成、试验、采用与改进

适用：忏悔原版 J835、Isaac、全解锁槽 1。目标是让 DeepSeek 编写可复用战斗能力，通过少量现场测试尽快在当局采用，并根据实际效果改进。允许探索失败，评价同时包含清房、非主动损失、有效输出、资源和耗时。

当前已实现 EID 单道具查询入库、限定属性的通用构筑适配、69 的参数化时序程序、妈妈的菜刀 114 的 DeepSeek 原生 JavaScript 组件、常驻批量运行器、短测后加载和跨进程复用。受伤采集、离线归因、API 总结与独立审核已交付，见 [归因审核](evidence/phase-2c-attribution-review.zh-CN.md)。菜刀战后模型反馈选择保留，修订后的局内试用尚未发生；实机证据与支持边界见 [道具适配证据](evidence/phase-2c-item-adaptation.zh-CN.md)。

## 1. 按能力组合，而非按道具复制控制器

| 效果 | 负责能力 | 处理方式 |
|---|---|---|
| 伤害、射速、移速、射程等数值 | 通用构筑适配 | 读取实际面板，不重复叠加 EID 数值，不逐道具生成代码 |
| 飞行、体型与碰撞 | 移动/几何配置 | 使用实际碰撞状态，与攻击穿障分开 |
| 蓄力、连发、释放与取消 | WeaponTiming | 根据输入与出弹反馈维护状态 |
| 多发、穿透、反弹、追踪、分裂、激光 | AttackModel | 发射与攻击形状、轨迹、命中和在途攻击 |
| 瞄准与目标偏好 | AimPolicy | 四向瞄准、预测、甩弹和目标评分 |
| 武器所需距离和站位 | PositionPreference | 为宿主移动候选提供武器相关评分 |
| 输出收益、过量攻击和机会窗口 | AttackUtility | 与实际击杀、耗时及损失共同评价 |
| 自伤、爆炸、亡语和残留 | EffectModel | 补充后果预测，不删除宿主已观察危险 |

纯属性分类由宿主明确维护；不能仅因面板改变就将未知道具判成纯属性。1、4、12、27、32、50 使用实际面板适配，20 读取实际飞行状态；已可用组件不因属性变化自动重写。魔法蘑菇含体型和健康变化，不能省略这些观测。69 已按构筑现场校准并实机验证了指定属性组合，其他机制组合仍需要单独证据。

## 2. 模型代码与求解器

推荐 Python 宿主求解器加常驻 QuickJS worker。Python 每帧统一准备公共数据、几何与移动候选，整套 JS 组件批量执行一次，组件之间直接调用函数；Python 汇总结果并执行实际输入。静态地形、代码和配置按版本更新，不每帧发送整份快照。不为每个候选或组件单独进行进程通信。

JavaScript 上下文按代码版本复用，允许普通函数、循环、数组和显式状态；不每帧重新解析源码。接口为 `init(context)`、`observe(observation, executedFeedback, state)` 和 `proposeBatch(context, movementCandidates, state)`。observe 只根据实际反馈推进一次，预测候选不视为已执行。显式 state 用于记录和恢复，隐藏状态问题通过测试、诊断与重置处理。

模型可修改获准职责的算法、参数、适用条件和测试建议，可提出宿主观测或通用原语缺口。宿主保留系统 IO、凭据、真实按键、控制台、存档、预算、结果统计及版本加载权限。模型材料不含系统访问接口。运行时间/内存限制与 worker 超时终止用于处理失控计算，不要求先证明打法在所有场景正确。

本机临时微基准中，紧凑输入、8/32 个敌人的常驻 JS worker P95 约 0.28/0.83 ms；重复创建上下文或发送完整快照会增加开销。该结果仅帮助选择接入方式，不替代完整控制链路的实机测量。现阶段无需因语言差异重写整个 Python 求解器。旧 AST 程序继续复用，实际热点出现后再局部优化。

## 3. 尝试、采用与复用

能力状态为 candidate → probe_passed → trial → usable；明确故障可转 quarantined。usable 表示在记录范围内有使用证据，不等于所有组合正确。新组合优先复用已有能力和必要短测，出现缺口或偏差才开发代码。

流程：识别道具/组合 → EID 与本地经验 → 缺口分析及候选代码 → 基本运行检查 → 清房节点短测 → 当局试用 → 战斗/受伤反馈 → keep/revise/probe/defer。首次短测最多 4 游戏秒，关键问题未回答时才进行第二轮，总计最多 10 秒。无怪宝箱房、起始房或已清普通房按实际敌人、炸弹、弹体与机关检查，不按房间名称自动认定适用。

短测确认可出弹、可释放、攻击形状和必要状态；实战负责补充命中、输出与损失证据。不能在空房证明的穿透/多目标收益记为待观察，不作为永久拒绝理由。基本检查和关键行为可用即可试用；在宿主持有的暂停边界切换，更新构筑/目录并废弃旧结果，无需重启。战中策略修订可在暂停检查后进行短试，不要求每次都离开锁门房。

回退仅在旧组件适用于当前实际构筑时成立；换代码不能撤销已拾取道具。没有兼容实现时暂停修复或结束本次探索，不能套用普通泪弹冒充兼容。

探索默认：无有效操作 2 秒触发诊断，已确认蓄力可延长至最多 5 秒；8 秒无有效战斗进展触发诊断；15 秒无进展或战斗 90 秒明确失败。单版本非主动损失达到 1 心、房间学习累计达到 2 心，或剩余有效生命不超过 1 心时停止相应试用。回血不抵扣损失。这些是停止条件，不保证避免死亡。

## 4. 反馈与优化

事实、来源说明、模型假设与实机结果分开。EID 说明按查询保存在单道具库，本地遭遇、测量、代码、试验与归因位于智能体经验库和运行目录。源码、构筑、代码版本和实际采用动作绑定，防止把未执行候选记为实战效果。

DeepSeek 根据反馈选择 keep/revise/probe/defer。不是每次受伤都修改代码；不以停止射击或消极绕行为默认优化。模型候选和建议无需先获得完整因果证明，但试验必须明确要验证什么，结果不得覆盖已有失败。

M2-C 首轮已发现：模型能够描述来源类型并提出接触/受阻假设，但会混淆单位、方位和跨事件引用，且经常退回泛泛的“补日志”。推荐先用代码提供相对位置、碰撞余量、短时运动与每个威胁的预测贡献，再向模型提供一个相关函数和可修改参数。不要仅扩展提示词，也不要将当前归因文字直接当事实自动改代码。具体案例和下一步由归因审核维护。

## 5. 边界、预算与后续范围

当前阶段总请求上限 24，首轮归因子上限 3，实际请求、失败和取消都持久计数。首轮已用满子额度并停止；不能以换目录、换房或重启重置。付费与研究政策统一见项目 README，不默认追加消融或大样本胜率实验。

当前道具适配矩阵为属性组合、基础69、69加属性、妈妈的菜刀114及114加属性。新模型组件以菜刀的蓄力、放刀、回收和武器站位为目标；穿透、多发与激光暂缓。114与69的特殊协同另列，不在本轮宣称支持。宿主可使用指令初始化道具或测试场景，随后正常移动射击；辅助初始化、实际损失、失败和代码作者分别记录。当前状态与行为级验收见M2-C计划。

主动消耗品、特殊生命、Eden 和随机生成机制不作为当前前置。Dataminer（481）与 TMTRAINER（721）分开；动态生成对象使用 run-local 身份，未知效果可成为后续专项探索，不能凭名称或短时未受伤宣称掌握完整机制。它们不阻止普通武器能力先交付。
