# M2-B 设计：DeepSeek 机制程序与道具扩展

状态：待实现；M2-A 不依赖完整程序运行器。当前 DeepSeek 只配置已有组件，工程 Agent 编写的宿主代码不计为模型自主开发。来源接口见 [知识库合同](knowledge-project-interface-plan.zh-CN.md)，被动学习/P7 见 [学习机制](eid-local-learning-plan.zh-CN.md)，基础组件 DTO 见 [组件合同](component-contract.zh-CN.md)。

## 1. 道具映射到能力，不映射到整套控制器

| 效果类别 | 需要改变的职责 | 推荐处理 |
|---|---|---|
| 伤害/射速/射程/移速等数值 | BuildCompiler、收益与运动参数 | 用实际面板映射；不为每个数值道具生成代码 |
| 飞行、体型、玩家碰撞 | Movement/Collision 与路径缓存 | 与射击穿障分别建模 |
| 蓄力、按住/释放、连发 | WeaponTiming | 新状态、等待证据、取消和释放后果 |
| 追踪、反弹、穿透、分裂 | Trajectory/HitEffect | 组合次序与重复命中约束；未知组合明确不支持 |
| 激光、近战、爆炸、遥控 | Emitter/Timing/Trajectory/Consequence | 匹配的新攻击形状、时序与危险模型；不能回退普通泪弹 |
| 跟班、轨道物、残留攻击 | 攻击来源与归属、被动输出、站位 | 不将全部弹体当成玩家可控输入或校准样本 |
| 特殊生命、复活、角色变化 | HealthModel 与资源/生存语义 | 独立策略，不能只改 hp 阈值 |
| 主动、卡牌、药丸、传送 | 有成本的 InteractionExecutor | 槽位、边沿、授权、后置条件及未知结果 |
| 随机/程序生成机制 | run-local 效果观测与缺口 | 默认拒绝/禁用，不能凭名称恢复完整机制 |

多个道具可共用一个能力实现，一个道具也可能同时改变多个职责。非交换机制必须有经过验证的组合规则；不按 ID 或拾取顺序随意排序。能力可观察、可预测、可控制与已验证应分别记录。

## 2. 模型产物等级与推荐方案

| 等级 | 产物 | 是否满足 M2-B |
|---|---|---|
| L0 | 既有组件 ID、参数、切换规则 | 不满足，仅为配置 |
| L1 | 类型化 AST，含新条件、局部状态和有界时序逻辑，调用受信任原语 | 首版目标 |
| L2 | 原语不足时的纯计算算法模块 | 后续评估无 WASI 的 Wasm/持久 worker 等隔离方案 |

不将模型 Python exec/import 到控制进程，普通子进程或 try/except 也不等于完整权限与预算隔离。L1 自行解释限定 AST、有限表达式和有界循环，提供指令/内存/输出上限，不使用 Python eval。

首例优先选一种原版可观测、可独立验证的简单弹道修饰或蓄力时机。若语言只能选预制武器，就没有满足程序开发目标；若机制超出原语表达能力，返回 requires_host_primitive，由工程侧补通用原语，不偷偷改写为手工组件后记成模型产出。

## 3. 输入、输出与独立工具

SkillRequest 包含：能力缺口、目标构建/接口、当前构筑签名、适用来源与反例、最小快照、组件合同、可用原语、允许状态、预算和失败样本引用。model_prior 与 EID/实测来源明确区分，不向模型发送密钥、存档或无关目录权限。

允许工具为 lookup_item/lookup_interaction、inspect_capabilities、get_sdk_contract、run_candidate_checks、replay_fixture、submit_candidate；宿主验证工具参数和路径。候选基本结构如下，ID 仅作示例：

```json
{
  "component_id": "weapon.example_release",
  "interface_version": 1,
  "kind": "bounded_program",
  "target_build": "1.7.9b.J835",
  "provides": ["release_timing"],
  "requires": ["observed_charge_state"],
  "state_scope": "room_and_build",
  "source_refs": ["versioned-evidence-id"],
  "assumptions": ["requires validation"],
  "program_artifact": "candidate/program.json",
  "test_artifact": "candidate/proposed-tests.json",
  "fallback_policy": "compatible_release_or_no_fire"
}
```

源码哈希、真实模型/请求、作者、验证结果与发布时间由宿主补写，不能信任模型自报“已验证”。候选只写专用产物目录，不能修改宿主、安全、独立测试期望或 Judge。

## 4. 开发与发布生命周期

资料整理/适用性检查 → 候选生成 → 本地独立验证 → 反馈具体失败 → 最多两次修复 → 影子/试用 → 发布或拒绝。已有兼容程序命中时直接复用。配置规划与代码开发分别计费，所有工具后请求、重试与修复都计入实际 API 总账。

版本状态为 draft → validated_offline → shadow → trial → supported，可随时 rejected/quarantined。supported 限定构建、能力组合与证据范围；不是全游戏正确性声明。

| 验证层 | 必须证明 |
|---|---|
| 解析/类型/输出 | 有限数、合法方向、候选/路径上限、上下文、单位和期限 |
| 能力组合 | 前提真实存在，当前武器及回退兼容，未知组合被拒绝 |
| 权限/预算 | 无文件/网络/环境/进程/直接输入访问；失控代码不会占住控制主线程 |
| 状态性质 | 同帧重复求值无重复消费，房间/构筑切换复位，停止与取消有界 |
| 独立语义 | 工程维护夹具、真实反例与变形测试；模型自写测试仅作补充 |
| 性能与实机 | 冷启动/稳态/最坏输入满足控制预算；实际正常战斗有效，离线回放不冒充反事实模拟 |

初始性能目标可设 L1 单模块约 2ms、新增模块总稳态约 5ms，最终由本机测量冻结；指令燃料保证终止，墙钟计时发现宿主异常。只在计算结束后量时不能保证硬期限。

发布在已确认的入房/清房暂停边界进行：释放输入、核对构筑、锁定候选与目录版本、清理受影响状态、废弃旧异步计划、恢复。战中可生成候选但不热装未验证源码。回滚程序不会撤销已经拾取的道具；无兼容版本只能有限避险或明确不支持。

## 5. 随机与错误道具的处理

Dataminer（481）不是 TMTRAINER（721），也不能套用其他 DLC/扩展版本的描述。首版对未适配主动随机效果禁用使用；未来使用后必须根据实际属性、临时效果与攻击行为重新编译，不能只监视库存 ID。

TMTRAINER 和不可识别生成物首版拒绝拾取并避让。原版动态库存不能完整枚举，固定 EID 说明不能解释某个随机生成实例的全部触发；全解锁场景也不能仅靠检查是否持有 721 排除所有错误道具。已被动获得时记录 run-local 未知对象、触发/后果和失效原因，无法可靠控制则报告不支持。

REPENTOGON 的程序物品接口属于可选独立辅助环境，当前未接入；即使可读生成规则，仍需实现自伤、随机触发、传送和连锁后果。暂未触发危险不证明其不存在。不要为学习反复主动受伤，也不以读档擦除正式失败。

## 6. 分工与完成条件

开发 Agent 负责观测、输入/预算/安全、通用原语、隔离器、独立夹具、发布和基础机制；DeepSeek 负责缺口分析、候选程序、根据失败的有限修复与可检索摘要；宿主独立决定发布和适用范围。

M2-B 完成至少需：真实模型新程序与可说明的行为变化、独立验证、正常实机试用、损失/时间/作者证据、另一次启动从技能库复用。人工接管修改标明工程作者，不能记为模型自主完成。无法保证模型永不犯错，只能让错误可检测、有界隔离、可回退。

主线继续 Isaac；普通 Eden 在机制替换与健康语义成熟后用作独立泛化集，记录初态/种子/Token。Tainted Eden 的战中重构另列。它们不作为 M2-A/M2-B 的额外前置，不以增加随机性代替针对性机制验证。
