# 道具知识库与 DeepSeek 组件开发设计

日期：2026-10-26。适用构建：忏悔原版 `1.7.9b.J835`。状态：第二、三阶段实施设计；本文件不表示知识数据库、自动编码或 REPENTOGON 已接入。

独立知识库的数据所有权、分层、查询 DTO、数据包与本项目 Gateway 接口见 [知识库项目接口计划](knowledge-project-interface-plan.zh-CN.md)。本文件负责道具决策与技能演进；跨项目数据交换采用该接口合同。

当前外部道具来源为 EID，学习过程与安全节点测试采用 [EID 与本地经验学习计划](eid-local-learning-plan.zh-CN.md)。固定说明包与本地经验分开管理，LLM 自身知识作为有来源标记的推断；不默认启用 Wiki 抓取。

## 1. 决策摘要

1. 第一次**可识别地遇见**物品时查询固定 EID 说明包及相关本地经验；缺少证据时记录 EID 导入缺口或本地学习任务。允许条件明确的安全节点测试，采集不进入游戏控制路径，未知效果不能靠无限等待解决。
2. 将“道具事实”“当前构筑的有效能力”“控制算法实现”“实机经验”分开存储。拥有 Wiki 描述不代表拥有可执行策略。
3. DeepSeek 分为战术规划与组件开发两个角色。开发 Agent 提供内核、协议、通用原语和独立验证；DeepSeek 应承担新增机制的候选程序与修复。
4. 普通属性变化优先用数据映射和现有通用组件；确实缺算法时才生成代码。无需为每个道具编写一个独立状态机。
5. 不承诺模型开发永不出错。目标是让错误可检测、可隔离、可撤回，并限制在未发布候选或有明确能力边界的模块中。

## 2. EID 数据来源与适用边界

外部道具说明固定使用 [External Item Descriptions](https://github.com/wofsauge/External-Item-Descriptions)。导入包记录 commit、文件哈希、语言、游戏构建与配置；不在运行时跟随 master 更新。官方发布页列有 Repentance 1.7.9b 支持，具体 J835 接入仍需本地验证。[发布记录](https://github.com/wofsauge/External-Item-Descriptions/releases)

EID 的 `rep` 目录不能直接当作完整数据库：旧条目可能继承基础目录，版本覆盖与条件描述受加载逻辑影响。导入器还原适用的基础/覆盖关系，保留原始标记与说明；不混入 `rep+`/`rgon` 的专属效果，不在宿主执行外部 Lua。无法解析的条件明确标为未知。

首版优先离线说明包；需要当前构筑条件描述时再评估游戏内 EID 导出，增加模组后核对输入、性能与信息可见性。EID 可提供道具说明，不等于完整的敌人模型或精确物理引擎；动态错误道具也不能仅靠静态条目确定。

本地经验来自结构化观测、有限测试和实际战斗，LLM 自身知识只作为推断来源。原始 EID、局部观测和模型推断分开保留；冲突不得由最后一次写入覆盖。学习更新经验和技能库，不代表训练模型权重。

EID 内容的复用/分发条件需明确，原始说明不默认进入本项目 Git。当前档位不启用 Wiki 网页抓取或反爬处理，资料缺失进入 EID 导入检查或本地学习任务。具体流程见 [EID 与本地学习计划](eid-local-learning-plan.zh-CN.md)。

## 3. 首次遇见与本地数据库

### 3.1 查询语义

“首次遇见”是本版本、本辅助档位下首次看到可识别物品，发生在拾取之前。以 `kind + item_id + game_build` 查询，不用中文名作为主键；收藏品、饰品、卡牌和药丸分别命名空间。

对于被遮蔽的物品/未识别药丸，默认保留未知。即使结构化接口能揭示其隐藏 ID，也要由独立 `reveal_hidden_items` 辅助开关决定是否可用，不能悄悄扩大当前权限。未知身份也保存 `encounter_id` 与可见证据。

```text
encounter
  -> identity/visibility check
  -> query pinned local knowledge package
  -> return knowledge bundle (including unknowns)
  -> capability mapping
  -> choose pickup / defer / skip / request new module

missing facts
  -> classify as EID import gap or local learning question
  -> reprocess pinned EID data, or design a bounded experiment
  -> preserve evidence, uncertainty and applicability
  -> adopt a new EID package or local experience revision at an allowed boundary
  -> future decisions retrieve both description and local evidence
```

首版使用 Python 自带 SQLite，不需要额外数据库服务或向量数据库。独立知识库管理可写工作库，并发布不可变只读包；本项目另存遭遇、构筑、技能与经验库。工作库使用单写入队列、WAL、唯一键与事务；发布前完成 checkpoint。实时控制线程只读内存快照；联网、解析和数据库写入不进入逐帧路径。

### 3.2 建议表结构

| 表 | 所属项目 | 核心字段 |
|---|---|---|
| `item_identity` | 知识库 | kind、id、game_build、名称/别名；静态身份 |
| `knowledge_source` | 知识库 | URL/仓库路径、provider、revision/commit、正文哈希、抓取时间、许可、访问状态、适用版本 |
| `mechanic_fact` | 知识库 | item key、作用域、触发、效果、前提、冲突/优先级、证据等级、source refs、审核状态 |
| `lookup_attempt` | 知识库 | 来源请求 key、时间、HTTP/解析结果、重试时间、失效/负缓存原因 |
| `encounter` | 智能体 | run/floor/room/visit、帧、物品实体身份、可见性、价格/轮换、查询/决策/实际拾取结果；错误道具为局内实例 |
| `build_snapshot` | 智能体 | 实际库存与临时效果、能力图、build_revision、证据帧、未知效果列表 |
| `skill_version` | 智能体 | 组件 ID/版本、接口版本、能力前提、作者/model、源码/程序哈希、来源 refs、状态、父版本 |
| `validation` | 智能体 | 模块哈希、输入夹具哈希、独立检查结果、性能、实机适用范围、失败反例 |
| `experience` | 智能体 | 机制签名、房间/构筑特征、行动摘要、损失、结果和原始轨迹路径；区分相关与因果证据 |
| `enrichment_outbox` | 智能体 | 幂等需求、遭遇引用、任务状态和待采用 dataset |

允许保存的正文另存为按内容哈希寻址的本地文件，数据库保存指针；默认不入 Git。保留自己的结构化总结、来源指针与许可允许的必要摘录，不把缓存当可随意公开的内容集。

运行时仅查本地 EID 包与经验，不发起网页请求。资料包获取在独立导入流程完成；缺失、未解析、版本不明或冲突都有显式状态，禁止把检索失败写成“无效果”。高风险问题进入独立实验待办，不自动调用其他网站补齐。

缓存键包含游戏构建、来源修订/内容哈希和解析器版本。新资料与旧资料冲突时保留双方，触发离线核查或实测；版本变更不覆盖已有运行引用的旧知识。

### 3.3 程序生成道具

错误道具不能用 `item_id` 跨局复用机制。至少使用 run ID、道具实例/生成身份、效果描述哈希（若可读）、来源帧组合标识。相同负数或显示名称在另一次运行不能被假定为同一机制；无法读出效果时存未知对象和事件轨迹。

## 4. 道具能够改变什么

下表是控制器的设计分类，不是已经实现的道具覆盖清单。机制事实应以目标构建资料和实际观测确认。

| 变化类型 | 对控制器的影响 | 组件责任 |
|---|---|---|
| 伤害、射速、射程、移速、弹速、幸运、体型 | 时间窗、击杀估计、移动余量和碰撞半径改变 | 面板观测与校准；不必逐道具写算法 |
| 飞行、穿障、碰撞变化 | 路径和射线通行规则不同 | 几何能力适配，地面危险分类；飞行不等于免疫所有伤害 |
| 多发、散射、连发、交替发射 | 攻击原点/方向/时间和命中覆盖不同 | 发射模式与收益聚合 |
| 蓄力、激光、刀、近战、遥控武器 | 按住/释放、攻击范围、姿态限制、冷却不同 | 独立武器适配器和输入时序 |
| 追踪、穿透、反弹、分裂、回旋、环绕、延迟弹体 | 直线命中预测不再成立 | 可组合弹道修饰与仿真；不能只改命中分数 |
| 爆炸、火焰、地面残留、敌人死亡触发 | 自伤、连锁爆炸、清房后危险和安全开火变化 | 攻击足迹、友方危险、死亡事件适配 |
| 跟班、轨道物、额外可控实体 | 输出来源和站位收益改变 | 发射器集合；第二可控身体是新的控制能力，不能假装只是伤害加成 |
| 主动、卡牌、药丸、充能方式 | 有限资源、冷却、使用时机、未知效果 | 交互策略和资源账本 |
| 心型、护盾、伤害替代、复活、角色变化 | HP 算法、死亡语义、可承受风险改变 | HealthModel、复活状态机和角色适配 |
| 物品重置、临时效果、随机效果 | 没有拾取也可能换攻击/移动机制 | BuildCompiler 的事件和周期核验 |
| 房间/地图/掉落/传送变化 | 路线、价格、支路价值、地图身份改变 | FloorDirector 与经济策略 |
| 视觉/音效扭曲 | 屏幕与结构化几何可能不一致 | 信任物理观测并保留视觉偏移标记，不从贴图偏移推断碰撞改变 |

组合按有向依赖处理：物理移动能力、主武器/额外发射器、弹道修饰、命中/死亡触发、资源与地图效果分别汇总。互斥武器和特殊协同采用经过验证的优先级规则；未知组合不会因每个单品都认识而自动成为已支持。

BuildCompiler 输出至少包含：有效武器集合、按住/释放行为、发射器、弹道修饰、伤害与冷却观测、移动碰撞能力、健康模型、资源操作、未知机制、版本号。用增量重建替代只比较收藏品列表；临时效果、饰品、主动使用和重置均可能触发更新。

## 5. 数据破解、错误技与错误道具

### 数据破解：Dataminer，ID 481

[原版说明](https://isaacguru.com/wiki/isaac_repentance/c481)描述了属性增减、房间内随机泪弹效果与视觉扭曲；贴图变化不等于碰撞体变化。不能套用 Repentance+ 的“使底座道具错误化”说明到 J835。

处理策略：首版不主动使用未知/未适配的随机效果道具；支持后，每次使用都产生一次能力变化事务，重新读实际面板和有效弹道，不只监视库存。临时效果在换房后的失效也要更新。维持结构化几何控制，检查攻击行为与预测残差；随机效果尚不支持时禁用主动使用，不能承诺调用后一定能恢复旧构筑。

### 错误技：TMTRAINER，ID 721

它使后续物品成为带随机效果的错误道具；Wiki 能解释生成机制，不能列出某次运行中每个生成物的完整策略。[原版说明](https://isaacguru.com/wiki/isaac_repentance/c721)

当前原版方案：默认拒绝主动拾取错误技及不可识别错误道具，将其作为避让对象并记录；并非所有游戏物品都值得拿。全解锁存档还需要考虑错误道具通过其他已解锁机制出现，不能只检查是否持有 721。[Corrupted Data 说明](https://bindingofisaacrebirth.wiki.gg/wiki/Corrupted_Data)

若已被动获得：建立 run-local 未知效果对象，监视使用、受伤、击杀、清房和换房等事件；根据已证实的效果更新威胁和构筑。不主动为“学习”反复受伤、触发未知主动或重开抹除失败。无法分辨的危险允许报告不支持/失败。少量观察未触发某效果，不证明不存在低概率危险。

可选增强：REPENTOGON 的 [ProceduralItemManager](https://repentogon.com/ProceduralItemManager.html)、[ProceduralItem](https://repentogon.com/ProceduralItem.html) 和 [ProceduralEffect](https://repentogon.com/ProceduralEffect.html) 文档提供程序生成物品及其条件、动作和概率的读取接口。EID 也注明详细错误道具信息依赖 REPENTOGON。这比静态 Wiki 更适合解析特定实例，但须验证目标版本兼容性并作为**单独辅助环境**验收，不能声称当前原版桥接已经能调用，也不默认安装。

即使读到程序效果，也仍要建模自伤、随机触发、召唤、传送与连锁行为；可读不代表安全、更不代表一定值得拾取。

## 6. DeepSeek 的真正开发职责

### 6.1 三种产出等级

| 等级 | DeepSeek 产出 | 例子与验收含义 |
|---|---|---|
| L0 配置 | 已发布组件 ID、参数、切换条件 | 当前实现；不算写代码 |
| L1 机制程序 | 带类型、局部状态、条件和有界循环的受限程序，组合受信任数学/几何原语 | 实现一个新的释放时机、弹道修饰或敌人阶段策略；可由确定性解释器执行，属于程序开发而非只选现成 ID |
| L2 算法模块 | 对现有原语不足的机制生成完整纯计算模块 | 后续可用无 WASI 的 WebAssembly 隔离模块；能力与性能经过独立验证后发布 |

M2-B 先实现 L1，保留 L2 接口。L1 必须允许表达新的控制逻辑；如果语言只能选择预制武器，则没有满足自动扩展目标。若一个新机制超出语言能力，应输出 `requires_host_primitive`，让工程侧补通用原语，不让模型伪造结果。

不建议首版把模型返回的任意 Python `exec/import` 到控制进程。普通子进程和 `try/except` 都不是完整安全隔离。L1 使用自行解析的类型化 AST、限定表达式/有界循环、指令预算与有限内存，不调用 Python eval；L2 评估禁用宿主文件/网络导入的 Wasm、燃料限额和独立 worker。未知复杂源码不在实机等待时临时放宽权限。

### 6.2 开发输入与工具

`SkillRequest` 包含：目标能力缺口、游戏构建、接口版本、当前构筑签名、带来源和可信度的机制资料、最小匿名快照、已有组件合同、可用原语、限制与预算、失败样本引用。

允许工具：`lookup_item`、`lookup_interaction`、`inspect_capabilities`、`get_sdk_contract`、`run_candidate_checks`、`replay_fixture`、`submit_candidate`。所有工具由宿主提供并验证参数；网页文本不获得执行权限，源码和提示词中不包含 API 密钥、存档或系统路径权限。

开发结果的核心结构：

```json
{
  "component_id": "weapon.example_release",
  "interface_version": 1,
  "kind": "bounded_program",
  "target_build": "1.7.9b.J835",
  "provides": ["release_timing"],
  "requires": ["observed_charge_state"],
  "state_scope": "room_and_build",
  "source_refs": ["fact:versioned-example"],
  "assumptions": ["example only; not a verified item mapping"],
  "program_artifact": "candidate/program.json",
  "test_artifact": "candidate/proposed-tests.json",
  "fallback_policy": "compatible_release_or_no_fire"
}
```

哈希、实际作者模型、请求和响应、状态及时间由宿主补写，不能信任模型自报已验证。候选路径必须限制在专用产物目录；不能允许它修改其他组件或测试期望。

### 6.3 多轮过程与发布

`资料整理/能力识别 → 设计与候选程序 → 本地验证 → 将具体失败返回 DeepSeek → 最多两次修复 → 试用或拒绝`。已有机制和模块命中时直接复用，无需走开发循环。战术选择和组件开发分别计费、分别设置时限；一次失败不能无限请求“再试”。

模块状态：`draft → validated_offline → shadow → trial → supported`，任一步可进入 `rejected`/`quarantined`。`supported` 限定构建、能力组合与证据范围，不代表全游戏正确。

| 验证层 | 必须检查的内容 |
|---|---|
| 解析与类型 | 参数/状态/输出 schema；有限数；合法方向；候选数量、路径长度、尺寸和版本 |
| 能力与组合 | 缺少输入不能猜值；当前武器与回退一致；冲突优先级；临时状态有效期 |
| 隔离与预算 | 无直接输入、文件、网络、环境、进程访问；循环/内存/输出/执行时间有硬限额；控制主线程不等待失控 worker |
| 通用性质 | 确定性、同帧重复调用无重复副作用、房间/构筑重置、有限停止、保留未知风险、不能绕过安全门 |
| 独立语义 | 开发 Agent/工程内核维护的夹具、真实观察反例和变形测试；模型自写测试只作补充 |
| 性能 | 实际控制预算中的冷启动、稳态与最坏输入；超时采用已验证兼容策略，不只记录慢帧 |
| 行为 | 影子比较、受控机制测试、正常实机试用；离线轨迹不是新动作的反事实模拟器 |

第二阶段初始预算建议 L1 单次模块计算不超过 2 ms，所有新增模块稳态总预算不超过 5 ms；以本机测量决定最终限值，并保留整体控制 p95/p99 指标。AST 指令限额负责终止，墙钟超时负责发现宿主/运行器异常。L2 采用持久 worker，超时回退到前一个兼容版本或本地无攻击避险；不能只在同线程计算完以后检查耗时。

发布在入房或清房后的已确认暂停边界原子完成：固定模块版本、核对构筑、清理受影响状态、废弃旧异步结果、确认输入已释放后恢复。战斗中可以规划和生成候选，但不热替换未验证源码。紧急策略来自已发布模块。

**程序版本回滚不会撤销游戏里的道具效果。** 已拾取新武器后只能回退到兼容实现；没有兼容版本时只保留可用移动/避险并报告不支持，不能假装换回普通泪弹，更不能通过读档把正式失败抹掉。

### 6.4 两类开发者的分工

- 开发 Agent：观测协议、动作内核、安全门、状态账本、通用原语、隔离器、独立验收、发布工具和必要的基础模块。
- DeepSeek：遇见新机制后读资料、决定复用/组合/开发、实现候选程序、解释假设、根据真实失败修复，并维护可检索的模块摘要。
- 宿主判定器：独立决定能否发布，记录由谁编写；人工接管改写必须单独标注，不能记为 DeepSeek 自动完成。

安全原语和发布器不开放给运行中的模型改写；该限制不妨碍模型在约束内创造新算法。首个验收必须看到“新程序内容与行为变化”，不能只看到一次 `llm_configured=true`。

## 7. 是否改用伊甸

**第二阶段继续 Isaac；Eden 作为后续独立测试集。** 普通 Eden 的初始属性、生命和物品随机，开局消耗 Eden Token；它适合检验构筑泛化，但同时引入更多变量，并不能自动补全罕见道具或协同覆盖。[Eden 资料](https://bindingofisaacrebirth.wiki.gg/wiki/Eden)

建议顺序：Isaac 随机种子 → 固定房间与目标机制的离线/初始化测试 → 少量普通 Eden 初始构筑 → Eden 正常完整长局。开发初始化测试与正式正常开局分开记录。

Eden 的种子随机性不等于“每次重开都独立抽样”；构筑生成受种子影响，记录种子与完整初态，不能挑好装备才开始计数。全解锁并不保证无限 Token，基线另记余额和恢复方式；当前目标止于 Mom，不能假定每次成功都补回 Token。

Tainted Eden 的受伤重置将构筑变化变成战中高频事件，远超普通 Eden 的测试意义，留到动态重构链路成熟后再纳入。

## 8. 后续交付的验收底线

首次遇见的知识记录可以是“未知且来源阻塞”，但不能静默缺失；第二次遇见不能重复无意义联网。来源、版本和推断必须可追踪。

自动开发至少完成一个非平凡机制：DeepSeek 生成候选 → 本地验证 → 正常实机使用 → 记录损失和耗时 → 下一次复用。故障注入要证明非法输出、死循环预算、版本过期和构筑不兼容不会绕过安全内核。程序正确性不能仅由另一个 LLM 打分。

这些约束只能将错误控制在工程可管理的范围，不能保证未知机制绝不失血或通关。更大随机覆盖、技能收益消融和模型优劣比较仍按 README 留待后续，不能因知识库和自动编程功能新增而默认启动昂贵批量实验。
