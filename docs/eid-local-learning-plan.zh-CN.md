# EID 与本地经验：运行机制及主动实验边界

状态：P5/P6 最小链路已实现，阶段能力及阻塞见[当前进度](progress.zh-CN.md)，准备审查仅描述历史基线。M2-A 使用有稳定样本身份的被动记录；通用自主实验 P7 关闭，M2-B/M2-C 的 69/114 必要局内短测已单独接入。本文维护学习机制，来源字段由 [知识库接口](knowledge-project-interface-plan.zh-CN.md) 定义，模型编程由 [M2-B 设计](item-knowledge-and-skill-evolution.zh-CN.md) 定义。

## 1. 四类成果与可信度

| 成果 | 来源与用途 | 不能推导的结论 |
|---|---|---|
| 来源说明 | 固定 EID 文本、提交、解析状态；解释道具机制线索 | 文本不等于已实现的控制能力，也不保证所有条件/协同覆盖 |
| 局部测量 | 实际面板、玩家泪弹和正常事件；校准当前机制参数 | 少数样本不能证明罕见效果不存在，不能自动推广到其他武器 |
| 战术经验 | 房间过程、损失、耗时、构筑和版本；选择兼容策略 | 单次零失血不等于稳定胜率或 LLM 因果收益 |
| 机制程序 | 模型候选代码、独立验证与发布记录 | 成功注册不等于安全、正确或实机有效 |

LLM 自身知识标为 model_prior，可以提出解释和实验设计，不能写成 EID 原文或已测事实。资料、模型输出与实际观测冲突时保留冲突，控制参数优先使用可靠实际状态。

## 2. 当前被动链路

`观察物品 → 保存首次遭遇前态 → 查询本地单道具库，缺条目则从固定 EID 包读取并入库 → 宿主支持/成本判定 → 拾取、跳过或延后 → 正常移动交互 → 核验消费与实际库存 → 构筑事务 → 房间使用 → 有新证据时保存局部结论 → 下一安全边界检索采用`。

当前拾取决定是工程支持表加成本规则，未调用 DeepSeek 阅读整条说明作收益推理。支持属性用实际面板，EID 数值不再加一次。未知物品进入避让和缺口任务，能力不足与物品不值得拿使用不同原因码；它们会决定后续开发优先级。

空房、暂停、已清房分别是不同事实。拾取动画中的 queued item 只证明待交付，真实库存变化才证明拥有；清房后交互可导致新的伤害、威胁或构筑变化，最终 RoomResult 必须重新检查。R1/R3/R4 的修复要求集中在准备审查与 M2-A A0，本文不重复列故障。

## 3. 观测、样本与采用事务

普通泪弹当前被动提取器只采集新出现、近玩家发射位置、玩家近乎静止且所有者可接受的泪弹速度。移动中的泪弹受运动继承影响，不能随意混入静止初速；旧在途泪弹和跟班归属不明样本不用于新构筑校准。

当前实现有 60 个速度样本窗口和 2,048 个实体去重窗口，至少 3 个样本才标为 observed。这个门槛是最低工程条件，不是统计置信区间。校准键绑定游戏构建、模型版本、攻击属性/物品与有效临时效果；不相干的飞行变化不应该作废攻击样本。

观察样本使用稳定身份，语义为 `(run_id, room_visit_id, projectile_instance_id, extractor_version)`，测量引用样本批次和提取参数。仅改变当前 snapshot_id 或进入下一房间不能重新生成独立证据；数据库重开后仍能去重。历史记录没有完整样本身份时保留审计、限制其证据等级，不补造原始引用。

采用事务为：固定知识/经验读版本 → 检索适用结论 → 过滤游戏/模拟来源 → 校验签名、单位、有限数与范围 → 在安全节点发布 BuildProfile 与新计划上下文。运行中的计划与经验版本不匹配时拒绝，不能在逐帧求解中联网或扫描 SQLite。

缓存值的 calibration_source 为 experience，calibration_samples 不增加。新实测与先前结论发生显著冲突时保存反例、撤销相应适用结论并重新检查依赖；不能把恢复先验等同于证明旧值错了。反例影响的范围必须跟原结论一致，模拟反例不能否定真实模式的测量。

## 4. 存储与记录

固定来源包由 isaac-knowledge 拥有，本项目不写其数据库。SDK 的单道具查询库 `artifacts/knowledge/queried-items.sqlite` 保存查过的条目、原始解析状态、来源/记录哈希和时间；同一数据集、道具与请求语言只存一条，查询不会自动成为测量或经验结论。项目用途配置允许说明进入规划和组件开发，来源权利元数据与未审核标记原样保留。查询复用与失败处理见 [知识库接口](knowledge-project-interface-plan.zh-CN.md)。智能体 SQLite `artifacts/agent-state/agent.sqlite` 拥有 encounters、decisions、pickup_results、room_results、measurements、claims、counterexamples、learning_tasks；原始大轨迹仍在运行目录。

| 记录 | 最小内容 |
|---|---|
| 遭遇/决策 | run/floor/visit、实体/可见身份、知识版本、构筑与健康前态、成本、理由、目标绑定 |
| 实际结果 | 事务 ID、动作确认、实际物品与资源变化、终态、错误及安全释放结果 |
| 测量 | 原始样本/批次引用、提取器版本、单位、有效样本数、混杂条件、来源模式 |
| 结论/反例 | 适用签名、证据引用、状态、采用版本、失效原因；不以 learned=true 混合全部语义 |
| 学习任务 | 缺能力类别、遇见频率/影响、关联证据、待办状态；不自动开启付费开发 |

每个运行都记录必要的失败和损失；不以随后回血或捡到资源抵扣先前非主动损失。来源模式至少区分 normal_play、development_initialization、simulated_game；开发场景可支持限定机制，但不能进入正常对局胜率统计。

## 5. P7 主动实验：条件性扩展，未实现

只有未知问题确实影响下一步选择、已有观测/经验不能回答、测试能区分竞争解释且后果可约束时才考虑主动实验。没有数据库记录并不是测试理由。普通面板属性不需要让模型再估计一次。

拟定模块分工：ExperimentGate 验证前提，Supervisor 控制时间/威胁/资源，Runner 经唯一输入通道执行，Extractor 产生测量，Publisher 决定是否形成有范围的经验。LLM 只能提出假设、原语和预期，不修改硬约束。

ExperimentPlan 至少绑定 context_ref、hypothesis_id、允许原语、测量定义、游戏更新/墙钟预算、资源上限、结束/中止条件和 inconclusive 处理。默认主动使用/炸弹/主动生命支出为 0；缺省不是无限。试验必须先确认恢复更新，完成后释放并观察残留，再按需暂停。

准入同时检查新鲜同房状态、实际构筑、无当前/待生成敌人和危险弹体、远离 TNT/机关/出口/未决定物品、可达退路及已知攻击后果。任何新威胁、伤害尝试、上下文变化、预算耗尽或观测过期都抢占；释放型武器可能在释放时攻击，因此未知蓄力武器不允许套用普通泪弹探针。

被动观测、局内低风险实验与独立训练分别计时计损失。空房实验不能验证真实命中率、实战 DPS、反射、亡语或低概率触发。证据不足返回 inconclusive，不反复测试直到得到想要的结论。

## 6. 后续推进顺序

M2-A 和有限机制编程已有各自证据，当前优先项由[进度](progress.zh-CN.md)维护。被动经验继续按稳定样本身份积累；自然获得足量样本后补实机跨局复用。69/114 的专用短测不等于通用 P7 已交付；只有真实依赖时扩展主动探针及危险中止，以能力缺口为单位开发，避免逐道具复制状态机。

所有付费、消融及统计原则统一见 [README](../README.md)。本文不另设一套 API 预算，也不自动触发实验。
