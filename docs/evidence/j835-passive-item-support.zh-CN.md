# J835 被动道具与 Boss 奖励支持

本文保留 231 个被动/跟班准入基线及对应实机证据；当前范围与商店/天使运营扩展见[运营验证](phase-3c-economy-validation.zh-CN.md)，不将本基线逐项改写为新版本成绩。

## 范围与实现

目标环境是忏悔原版 `1.7.9b.J835`、Isaac、普通难度、全解锁槽 1。Boss 奖励通过正常击败 Boss 后移动拾取；不使用控制台给予道具。固定种子 `3BYH A82R` 用于开发复现，不能代表随机种子胜率。

模组仅在主线第 1～6 层、普通维度、非失明诅咒且 Isaac 的底座身份可辨认时提供道具 ID；失明或身份条件不可核对时隐藏 ID。Python 先查询固定 EID 说明，再用 `item_capabilities.py` 判定普通泪弹输入是否仍适用。能力表按面板攻击属性、移动/飞行、生命与资源、独立跟班/附加输出划分。拾取后从游戏读取实际面板、生命、库存和武器类型；不按 EID 数值重复叠加。左/右眼非对称、随机属性和饰品生成明确保留修饰标记，攻击收益仍是近似值。

本机 `resources-dlc3/itempools.xml` 的 `boss` 池含 59 个唯一 ID，支持表覆盖 **59/59**；`treasure` 池含 407 个唯一 ID，其中 311 个是被动或跟班，当前正常拾取准入 **137/407**，占被动或跟班 **137/311**。总计登记 **231 个被动或跟班 ID**。`scripts/audit_item_support.py` 逐项核对固定 EID 英文记录完整性与本机 `items.xml` 的 passive/familiar 类型，审计结果没有缺失或误放行主动道具。覆盖表示可识别、拾取并保持普通控制链路；不是逐项战斗验证或价值排序。特殊主武器、多发、激光、炸弹主动行为和饰品构筑仍需对应组件。

普通首层路线的 frontier 优先级为可进入的宝箱房、未探索普通房、Boss 房。尚未发现宝箱门时仍继续探索普通房；宝箱门锁定且没有钥匙时先探索其他可达房间。房间图仅维护已观察门和实际通过的边，优先级由 `TreasureFirstRoutePolicy` 提供；未来商店选择和隐藏房探索需要各自的准入、代价与价值策略。宝箱房底座逐件经 EID 和当前构筑核对，无法兼容的特殊机制跳过。

## 宝箱房优先路线与移动陷阱

[首层实机报告](../../artifacts/runs/m3-treasure-pitfall-threat-retest/floor-report.json)和[原始轨迹](../../artifacts/runs/m3-treasure-pitfall-threat-retest/trace.jsonl)记录固定种子 `3BYH A82R`、规则控制、0 次 API 请求：访问房间类型的顺序为起点与普通房 → 宝箱房 `4` → 普通房 → Boss 房 `5`。宝箱房的 167 Harlequin Baby 有确认的正常拾取事务；随后击败 Little Horn，拾取 14 Roid Rage，经正常出口到下一层并恢复可行动。报告为 `FLOOR_COMPLETED`，非主动损失 0 半心。固定种子只证明这一条路径，不代表随机地图都能找到宝箱房或 137 个准入 ID 均已实测。

Little Horn 的 `291/2 Teleport Pitfall` 在飞行阶段 HP 与接触伤害均为 0，不能按普通 `hostiles` 列表过滤。危险场加入该实体的实际位置、速度与碰撞半径，并对碰撞尚未启用的移动阶段提前预测；清房边界则在已启用碰撞且贴近时继续视为危险。保留的[反例报告](../../artifacts/runs/m3-treasure-first-route-retest/floor-report.json)记录陷阱与角色重叠、损失 1 半心及 `POST_CLEAR_UNSAFE`；修复后的首层运行观测到陷阱，最近边缘间距约 15.7 像素，零失血并正常离层。该样本不能证明所有 Little Horn 攻击都可无伤规避。

## 验证边界

本地回归覆盖非失明的第二层可见性、失明和非普通维度的隐藏、Boss 与宝箱房奖励决策、构筑修订、跟班不重置玩家泪弹校准、随机/非对称标记、拾取后生命变化、路线优先级及零 HP 移动陷阱。实机只覆盖上述三个具体 ID 和固定种子局；59/59、137/407 是静态准入覆盖，仍需在随机局中记录更多道具的效果、战斗收益和损失。商店付费购买、恶魔房生命交易、主动道具使用及完整 Mom 长局不由本次证据确认。
