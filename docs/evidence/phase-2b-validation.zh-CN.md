## 4. 能力边界与后续问题

- EID 的组件开发查询仍因本地 `ai_input=unknown` 隐去正文。本次使用本地实测知识与 SDK，EID 仅提供可见身份和来源引用；没有借 display 向模型转发说明，也没有将未知策略改成允许。
- 道具由记录完整的初始化给予。本次没有实机证明自然生成底座的决策、接近和拾取交付；未知道具队列、发布后的狭窄拾取适用性及不兼容拒绝由本地测试覆盖。
- 首次试用有 stall/no_progress 边界 9/5 次，复用为 8/4 次；本地恢复次数 11/7，最长无进展 142/158 更新。它能清房，效率仍有明显改进空间；不将满蓄力和反复恢复包装成优质打法。
- 程序未充分利用目标血量与方向记忆，后续应针对真实失败/低效轨迹改进释放与重定向，优先完善观测及离线反例，不默认追加付费实验。
- 支持仅限校准列出的构筑。其他武器、额外道具/饰品/临时效果、错误道具及大量机制组合未交付；语法恢复也不是任意程序自动修复。
- 两次相同种子的开发试用只能证明当前机制链路及复用，不能作为独立随机样本，也不证明稳定胜率、完整首层或 SOTA。

原始对局位于 `artifacts/runs/<运行 ID>/`，每次保留 manifest、trace、report 和 mechanism-trial；机器汇总重新按初始化及房间身份核验统计，不修改历史原始记录。首例使用的机制采样与暂停释放失败见 [B0 探针证据](phase-2b-mechanism-probe.zh-CN.md)。
