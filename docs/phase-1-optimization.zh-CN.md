# 第一阶段优化：可恢复、可替换、安全主动的战斗控制

## 目标与验收

在忏悔原版中，以 Isaac 普通难度从初始房间正常出门，使用移动和普通泪弹清理首个战斗房。入房可暂停，战中通过本地恢复与异步 DeepSeek 诊断处理异常。其他攻击方式通过组件替换契约测试验证。

当前验收证明工程可行性：有真实的完整 LLM 清房记录、有效输入与清房证据，且本地测试和失效释放机制通过。优先使用已有记录、离线重放和规则控制器；付费调用只用于必要的少量完整流程。大样本 LLM 回归、配对和消融暂缓，后续实验清单与费用原则见 [README](../README.md#验证与付费-api-原则)。可行性通过不代表稳定胜率、资源性能或竞速优势已经获证。

未恢复停滞与战斗超时均为失败；提前停止、切换策略或重试不能消除失败记录。零观测失败只说明本次样本中的结果，不能推导任意房间的绝对安全。

## 组件契约

固定管线为：原子快照 → 武器/敌人/环境适配 → 时空威胁预测 → 目标与射击站位 → 移动和攻击候选 → 安全过滤 → 联合选择 → 唯一输入执行器。

武器适配器负责输入状态、射程、弹道与攻击阶段；敌人适配器负责行为预测、可伤阶段和死亡后果；环境适配器负责机关和持续危险。目标、站位、躲避、逃生和恢复分别注册真实实现。调度器不包含具体武器或怪物编号。组件不能发送输入、调用网络或访问其他组件私有状态。

公共契约包括 CapabilitySet、ThreatForecast、AttackProposal、MotionProposal、SafetyAssessment、ProgressEvidence 和 BoundaryEvent。目录声明前置条件、参数、单位、状态与预算。计划 v2 明确能力要求；v1 通过显式转换兼容。LLM 无权关闭安全和进展监督。

## 危险边界与恢复

进展证据包括同一敌人实例生命下降、可验证的击杀、固定站位路径成本减少至少 8 像素、必要障碍打开以及有证据和截止时间的攻击准备。实体消失、换目标、重建路径、规划请求和绕圈不算进展。

| 边界 | 条件 | 处理 |
|---|---|---|
| 无理由零动作 | 30 更新帧 | 本地恢复；60 帧仍未恢复则强制诊断 |
| 移动受阻 | 30 帧位移不足 8 像素 | 换路线；60 帧或重复发生则诊断 |
| 无效攻击/振荡 | 90 帧没有有效进展 | 修正目标、弹道或射击站位，并诊断 |
| 反复脱困 | 150 帧内两次恢复 | 更换策略并诊断 |
| 逃生余量不足/无安全候选 | 即时本地避险，持续 15 帧升级 | 不等待 LLM；选预测损失最小动作 |
| 真实受伤/机制失配 | 经观测核实 | 保留前后证据、修正预测并诊断 |

同一无进展事件在 1 秒本地恢复、2 秒强制诊断、4 秒进入独立确定性恢复、8 秒仍无进展判 STALL_UNRECOVERED。120 游戏秒为最后战斗上限。暂停不计游戏时间；切换计划不重置计时。合法等待必须来自已验证组件，不能由自由文本无限延期。

每房最多一个在途 LLM 请求，战中总请求预算六次（两次保留给严重边界），每次含一次修复总计最多 20 墙钟秒。迟到结果检查上下文和事件有效性，取消必须结束实际网络请求。

## 安全与进攻

近程精细预测 12 帧，逃生评估 45 帧，至少保留 6 帧撤离时间余量。误差边界包括碰撞半径、观测年龄、控制延迟、预测误差与制动距离。规划真实可达撤退路线，优先保留两个方向。不能仅以静态安全格比例代替包围预测。

击杀前评估亡语、爆炸、分裂和危险地面；预测危险应与实际生成实体关联。机关区分预警、活动、恢复与未知状态。清房后至少安全收尾 15 帧，最多 90 帧；收尾伤害计入本房损失。

先满足安全约束，再优先有效伤害和取得射击通道。安全收益达到阈值后饱和，避免无止境后退。普通泪弹有合法攻击机会时停火必须记录原因。命中评分是模型估计，不是真实概率。

## 实施与测试

提交顺序：监督与恢复 → 组件接口和计划 v2 → 站位、安全与主动输出 → 亡语机关和 LLM → 性能与实机证据。

保留现有回归，新增零动作、射空、绕圈、合法等待、实体变形、遮挡、围堵、死亡后果、过期规划、预算与替换测试。空间索引不能忽略可能接触的高速危险。决策预算 p95≤20ms、p99≤30ms，超预算使用最新状态上的简化避险。

研究性评测暂缓执行。其候选设计为：既有十种子回归、三十开发种子、冻结后五十新种子配对留出；参考门槛为两组各至少 48/50 清房且无未恢复停滞或总超时，LLM 平均失血≤0.4 半心。正式采用前需要单独确定样本量、预算和性能目标，不能把这些实验当作每次工程改动的必跑步骤，也不能把可行性通过写成这些统计门槛已通过。开发后不能继续称相同样本为留出。

每次保留源文件哈希、种子、基线、动作实际生效证据、边界与恢复、规划、伤害、停火理由和独立判决。失败保留在分母中，完整进程墙钟与战斗/暂停/清理分别统计。

## 验证范围

验证按改动影响选择，以少量必要的端到端证据证明完整启动与战斗链路。已有本地证据仍适用时，不重复付费调用。

| 改动 | 必须重验 |
|---|---|
| 启动、窗口与存档确认 | 启动单测、相应故障注入、少量完整流程 |
| 战斗组件、物理或危险预测 | 受影响机制用例、难例、离线性能与必要的规则实测 |
| 提示词、计划结构、组件参数范围或重规划时序 | 模拟响应与异步执行回归；必要时少量 DeepSeek 实测 |
| 网络与取消处理 | 优先模拟超时、断线、取消、旧计划拒绝与持续控制 |

未改变的组件可复用证据，前提是源码、配置与依赖一致，且保存哈希比较和 Git 差异。仅启动器改变时，不要求重复整套 DeepSeek 开发回放。复用证据保留原始版本与失败，不合并宣称新版本整批通过；部分完成的批次不能标为完整回归通过。后续研究若采用留出集，应冻结完整实现并明确停止规则，不能按已见结果挑选样本或更改判定。

优先使用本地验证排除启动、导航和物理故障，不因规则组通过而自动启动付费配对实验。确需研究性批次时，可以在预定门槛已不可能达到、预算耗尽或行政停止后结束未启动样本，但必须先让当前样本安全收尾，并保留实际启动数、全部已启动结果和未启动数量，不报告完整计划样本的胜率估计。

## 模块边界与扩展入口

实现位于 `SocketBridge/python/combat/`。

| 模块 | 职责 | 替换边界 |
|---|---|---|
| `components.py`、`catalog.py` | 可执行组件注册、能力声明、参数校验、组件异常隔离 | 新武器注册适配器与合法组件；新策略替换目标、站位或瞄准模块 |
| `controller.py` | 调用组件、联合评估移动与攻击候选、选择动作 | 不按怪物种类分支；组件输出统一提案 |
| `motion.py`、`geometry.py` | 玩家速度校准、扫掠碰撞、贴墙滑动、寻路和射击通道 | 物理模型与策略评分分离 |
| `threats.py` | 敌人行为适配、弹道与爆炸预测、可达撤退路线、攻击后果 | 新敌人替换预测和攻击许可；不修改动作执行器 |
| `navigation.py`、`environment.py` | 出门、危险地形、机关状态与通过条件 | 机关适配器单独扩展；未知机制保留失败原因 |
| `supervision.py` | 独立进展证据、危险边界、恢复升级、停滞判决 | LLM 与策略组件均无权重置或关闭 |
| `planner.py`、`runtime.py` | DeepSeek 请求、上下文验证、计划安装、唯一输入写入、收尾 | 网络调用与逐帧控制分离；只在动作边界安装合法计划 |

移动目标与射击目标相互独立：去往安全射击位置时，可以攻击途中的合法目标。攻击射线同时检查可能波及的危险敌人，不能因更换射击目标而绕过爆炸或不可攻击机制。普通泪弹可打开普通便便遮挡；其他障碍不会被当作可破坏目标。

无怪但未清房的房间进入环境处理流程。首版支持受限普通压力板：先避开炸弹和 TNT 连锁范围，等待实际状态变化，再移动触发；只有真实清房或敌人生成才算完成该机关阶段。火堆格参与行走避障，熄灭后才恢复通行。出门、环境处理与战斗分别有进展和时间边界。

空房探索保存已经观察到的普通开放门连接。当前房间没有未访问出口时，沿已知房间图返回仍有未探索出口的房间；不读取下一房间敌人或隐藏地图。逻辑节点使用房间编号，返回同一房间仍创建新的移动控制器和访问记录。搜索有最多八次换房的边界，不能在已耗尽的支路间无限往返。

伤害按整个任务累计，治疗不能抵销已经发生的损失；导航伤害也不能丢弃。战斗时间和战斗失血从第一次观察到实际堵门敌人开始单独累计。进入空房、机关房或者导航途中死亡，不会被计为零秒清房。

射击位置缓存只保存同一地形下的合法几何站位，不缓存动态起点的整条路径。缓存最多六十四个目标；改变地形、飞行能力、授权机关或开放门状态时失效。地形目标搜索使用已有评分的下界剪枝，不能省略可能更优的目标。性能基准分别记录冷缓存和热缓存，不能仅靠重复同一快照的热缓存结果证明逐帧预算。

角色可能因漂移或击退停在开放门缝内，超出室内可走网格。控制器可依据已观测的开放门，在完整身体扫掠检查下向室内退让；这条例外不授权向外穿门，也不能经过危险机关。模型在这种位置连续十二步原地受阻时，不能把零动作当作已验证的安全站位。主动穿门仍由导航组件单独负责。

## 运行与验收入口

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe run_first_room.py --local-only
.\.venv\Scripts\python.exe -m unittest discover -s SocketBridge/python/tests -t SocketBridge/python -q
.\.venv\Scripts\python.exe scripts/benchmark_combat.py --output artifacts/combat-benchmark.json
```

`scripts/qualify_phase1.py` 是全面研究性回归工具，包含多个付费 LLM 批次，不属于当前默认验收流程。只有单独安排此类实验后才使用，运行前应明确样本量和调用预算。

`run_phase1_batch.py --stop-after-failures 3` 可在五十例中第三次失败后停止未启动样本；`--stop-file <path>` 在停止文件出现时完成当前样本后退出。报告保存 `planned`、`completed`、`unstarted`、`status` 和停止原因。停止的批次始终返回失败状态，不得把成功完成的前缀当作完整批次。

`scripts/audit_phase1.py` 从原始轨迹独立重建判决与损失；`scripts/verify_phase1_qualification.py` 校验实际战斗、MANUAL 恢复、实现哈希、存档基线和依赖一致性。`scripts/package_phase1_evidence.py` 导出可入库的文本证据与原始轨迹哈希，存档二进制、游戏文件和 API 凭据不进入证据包。

自动启动必须观察到片头后的菜单初始化，以及菜单选择后新增的存档加载记录，不能以开机预加载记录代替。片头跳过与槽 1 存档确认各最多三次；其他槽无法在未知菜单位置安全重放左右选择，未获确认时直接停止。连上游戏后立即停止菜单按键。`scripts/probe_launcher_handshake.py --phase intro` 或 `--phase save` 故意丢弃一次预启动确认键，验证恢复与原生暂停；其输出单独标记故障注入，不计入正式战斗成绩。
