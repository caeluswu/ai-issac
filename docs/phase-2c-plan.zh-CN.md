# M2-C：可信战斗反馈与局内能力优化

日期：2026-10-27。首轮实现基线：`f0f2fb7`、`9c413c3`。已交付受伤采集、本地归因、显式 API 总结、独立审核和持久预算；结果见 [六例审核](evidence/phase-2c-attribution-review.zh-CN.md)。当前停止于首轮交付，不自动修改战斗组件，不推进 M3。后续能力架构由 [道具扩展设计](item-knowledge-and-skill-evolution.zh-CN.md) 维护。

## 1. 目标与职责

目标是为当局模型编程提供可操作反馈，同时记录清房、损失、输出和耗时。允许探索失败；未知或有争议的原因保留为假设，不要求完整因果证明才提出试验建议。

- 健康账本确认损失、骨心变化、主动支出和容器变化，归因不改变计分。
- DamageCapture 收集紧凑状态、伤害尝试、动作和候选，按事件保存窗口。
- 本地分析器整理来源、时间线、局部环境、实际动作、预测候选及缺口。
- DeepSeek 生成简短、有引用的诊断和一项下一步建议。
- 开发 Agent 对照原始轨迹审核；源码和提示词扩展依据审核结果决定。

## 2. 当前接口与存储

Lua PLAYER_DAMAGE_ATTEMPT 新增 schema_version=2、event_id、callback_frame、run/room、可空 source_entity 与来源可读状态。实体记录带身份、类型、位置、速度、半径和生成者；敌方弹体、激光和炸弹增加一致身份。事件外层 frame 保留回调/入队时刻，不随发送时刻变化。伤害 amount 仅为尝试值，不直接累加为扣血。

新运行由任务健康账本产生 damage_health_delta；离线回放优先消费该记录。旧轨迹使用健康账本重建并明确标注 legacy 模式；旧记录缺少主动成本意图或同帧回血时，不能恢复不可见的毛损失，也不能用尝试量补造结果。

DamageEpisode 绑定事件 ID、run/room、健康观察区间、前后健康、损失、原始行号和记录窗口。每次确认损失独立生成；前最多 90、后最多 30 个游戏更新，另有容量上限。换房、断线、死亡或结束会保存已有片段并标明截断。连续受伤不受 90 帧同类去重抑制。

运行目录的 damage/ 保存窗口及 analysis JSON，damage-index.json 保存索引和写入错误。来源轨迹与 manifest 保留引用，窗口内容哈希可核对。原始快照仍保留在 trace.jsonl，实时捕获不复制房间网格。后台线程完成分析和 SQLite 写入，持久化失败不会改写战斗胜负；原轨迹可重新提取。

智能体 SQLite 增加 damage_episodes、damage_analyses、damage_summaries、damage_reviews。来源窗口不同版本分索引，分析、原始模型回答和审核意见分别保存；不写 EID 说明库。

本地分析输出 direct_source、facts、hypotheses、missing_evidence 和 evidence 映射。来源类型不代表唯一实例，动作 ID 不证明移动回调执行，低风险候选是旧模型预测而非真实反事实。已记录的下一更新位置可与对齐的实际位置计算残差；旧轨迹没有预测点时明确缺失。

## 3. API 与审核合同

analyze_damage.py 提供 extract、summarize、revalidate、record-review 和 budget。extract 为本地操作；summarize 是显式付费入口，正常运行默认不自动调用诊断 API。未来房间边界自动触发仍未接入。

模型输入仅含必要事实、证据编号、局部环境、构筑、组件职责、代码上下文身份及输出示例，不发送整份轨迹或整个求解器。输出每例包含 summary、source、最多两个 hypotheses、counterevidence、missing_evidence、recommended_action、verification_test。

结构和证据归属由程序检查，语义由独立审核处理。反证可以是结构化声明或带引用的文本，不为表示差异追加请求。revalidate 只重验已有原文，不调用模型、不改变判断；无效引用的原文保留为 needs_review，不能自动采用。事实与审核不能覆盖原始响应。

首轮使用 DeepSeek，显式关闭思考、单次最多 4096 输出 tokens、HTTP 不自动重试。缓存按模型和实际输入识别，单纯修改本地验证代码不自动重发相同请求。空响应、坏 JSON、超时及取消保留请求与用量；失败默认返回缓存，额外重试必须显式选择且仍受预算限制。

预算位于 artifacts/damage-attribution/budget.sqlite：M2-C 共 24 次，damage_review 共 3 次。每次实际请求前事务预留，失败或取消不退款；未知用量保留为未知。源码、重启、任务目录不能重置额度。当前首轮 3 次已用满，未开放其他阶段的自动消费。

审核每例检查事实、因果强度、责任定位、建议可执行性、清房/输出目标和不确定性。结论为 reasonable、partly_reasonable、insufficient_evidence 或 incorrect，引用各自证据并另存。它不是模型自评，也不是自动规则评分冒充人工审核。

## 4. 后续工作与进入条件

下一步先提供代码计算的相对方向、距离/碰撞间隙、0.5–3 秒运动摘要、受阻情况及每个威胁的预测贡献，修复已复现的归因误读。通过相关函数与有限参数让模型提出一项可检验改动；不把不断加长提示词当成通用方案。

外部请求采用简短案例/证据编号，宿主保留完整身份映射和跨事件引用校验，减少重复哈希的token成本。已有轨迹能提供的特征先重算，避免把每次诊断都变成新的采样任务。

后续再实现常驻 JS worker、Python 求解器批处理、通用属性适配、局内探针与暂停边界加载、反馈修订及有限组合压力测试。旧 69 程序可复用，新组合的尝试和 usable 证据分开；一次清房不证明普遍正确。完整职责、限额、试用和回退语义见道具扩展设计。

## 5. 验证与完成边界

首轮需要：每次可观测损失可追溯、连续受伤不漏窗口、健康统计不变、API 原文及引用可检查、六例独立审核与明确下一步。当前实现满足采集和审查交付；模型因果说明仍须人审，自动优化没有交付。

已有 346 项全量测试通过；自审后定向测试及微基准的具体数量由验收证据维护，不为文档改动重做付费回归。新 Lua 来源字段通过实际 Lua 函数的桩测试，未追加 J835 实机采样。历史三次运行和六次受伤用于本轮审核，全部请求及失败保留。
