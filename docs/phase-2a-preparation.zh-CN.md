## 1. 结论

**架构方向合理，基础实现可复用；P0–P6 不能按“边界已全部闭合”处理。** 当前是普通泪弹、少量属性/飞行道具、规则拾取与被动标定的最小实现。四个离线复现的问题需要先在 M2-A 的 A0 工作包修复，再接连续楼层编排。无需重写实时控制器或先实现完整道具能力图。

历史 252 项测试和一次零失血实机清房说明已测试路径可行，不能覆盖所有组合边界。本次针对性运行 64 项现有测试通过，同时独立审查探针复现四个问题：测试通过与接口仍有缺陷可以同时成立。此次未启动游戏、未请求 DeepSeek、未修改运行控制代码；审查问题保持待修复。

## 4. M2-A 集成前还应落实的设计边界

- **单房入口不能简单循环。** `navigate()` 强制初始房间且只找普通门、最多搜索八房；M2-A 新增 FloorDirector，复用 navigate_door 的动作能力，独立维护整层图。
- **费用必须在客户端请求层计数。** 当前入房会规划，战中另有重规划次数；工具往返和修复可产生多次 API 请求。现有计数不是整局费用硬上限，A5 增加统一预算。
- **交互结果应分类。** 可选物品不值得拿、不可达或预算不足可以跳过；死亡、断线、未知构筑与失去控制是终止原因。不能把所有拾取 abort 都变成清房成功或把所有可选失败都升级为整局失败。
- **经验依赖应显式。** BuildProfile 已采用的版本与新发布的数据库版本允许暂时不同；只能在安全边界采用，采用与构筑重编译必须一致。KnowledgeBundle 向 LLM 提供的经验也要标记/过滤来源模式，不能只过滤本地校准值。
- **观测优先于解释。** EID 只给说明与来源；实际面板用于控制。原版动态物品不可枚举仍为 unknown。未知道具可避让，无法避免的强制未知须明确失败。
- **没有必要提前上全能力图、Wasm、向量库或全道具测试。** 先把上述四个边界和首层状态机闭合，新增机制再扩展合同。
