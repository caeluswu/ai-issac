# 第二、三阶段路线：首层、模型扩展与 Mom

当前：M1、M2-A 首层、M2-B 蓄力程序、M2-C 有限道具扩展及 M3-A 连续两层均有工程可行性证据。M2-C 的归因审核与菜刀组件见[归因审核](evidence/phase-2c-attribution-review.zh-CN.md)和[道具适配证据](evidence/phase-2c-item-adaptation.zh-CN.md)；M3-A 同局结果见[连续两层验证](evidence/phase-3a-two-floor-validation.zh-CN.md)。M3-B 至第四层与 M3-C 至 Mom 仍待实证。本文件维护里程碑与跨阶段取舍。

## 1. 里程碑与独立成功证据

| 阶段 | 目标与新增能力 | 完成证明 |
|---|---|---|
| M2-A | 正常首层探索、有限拾取、Boss、正常出口；普通泪弹及狭窄能力范围 | 同一 run 从起点到下一合法层，Boss/离层/存活可行动证据齐全；一次必要 DeepSeek 采用证据 |
| M2-B | DeepSeek 编写一个非平凡机制程序，经独立验证试用并复用 | 实际程序/作者/行为变化、离线验证与实机试用、另一次启动复用；调参或选择现成 ID 不算 |
| M2-C | 受伤归因与审核；属性、69及114的局内短测/采用与复用 | 六例审核、菜刀模型实机清房/底座拾取/进程复用、战后保留决策；修订后的局内试用未验证 |
| M3-A | 同一局连续完成第一、二层；跨层状态和全局资源预算 | 已有 J835 固定种子正常实机：两层 Boss 与出口、第三层可行动、累计损失 5 个半心；随机覆盖待测 |
| M3-B | 连续推进至主线第四层完成；新敌人、地形与装备组合 | 逐层损失/资源/耗时/失败和机制覆盖，不拼接独立局结果 |
| M3-C | 正常第一层开局至主线 Mom | Mom 实体/阶段/结束证据与存活可行动状态，同一 run 连续轨迹 |

主线目标是 Mom，不混用 Mom's Heart、It Lives 或 Mother。XL 会改变实际地图数量，不能用“换层六次”判终点；替代路线、Home、Boss Rush 等不是默认目标。具体构建、存档和辅助边界以 [任务契约](task-contract.zh-CN.md) 为准。

## 2. 为什么首层仍需要集成工作

单房已有输出、走位和避险基础，首层可行性的新增算法量有限；难点是状态连续性。物品消费、动画交付、清房残留、门落点、Boss 多阶段和离层必须有一致的身份及终态。已通过的 252 项历史测试和单房实机不能自动覆盖这些边界。

M2-A 不先实现全道具能力图。修复交互授权/终态/证据去重后，新增 FloorGraph、FloorDirector、ExitExecutor 与独立 FloorJudge；原有 RoomExecutor 和唯一输入通道复用。具体 A0–A7 顺序、预算、CLI 和验收不在此重复，全部由详细计划维护。

## 3. M2-B：模型代码扩展

选择已有原语能表达、但当前没有算法实现的一个弹道修饰或简单蓄力时序；选择前检查原版可观测性和可验证性。不从随机错误道具或全局重置开始。开发 Agent 提供通用原语、受限运行器、独立夹具和发布机制，DeepSeek 产出候选程序及有限修复。

首版采用类型化有界程序，保留未来纯计算模块接口。程序必须含新的条件/局部状态/时序逻辑，能在不改安全内核、预算和 Judge 的前提下工作。首例推荐巧克力牛奶的蓄力与释放，先确认原版观测；具体实施、费用和完成条件见 [M2-B 详细计划](phase-2b-plan.zh-CN.md)，长期设计见 [组件开发设计](item-knowledge-and-skill-evolution.zh-CN.md)。

## 4. M3：连续运行与长期风险

M3-A 新增 RunDirector，跨层创建新图并保留 run 账本、构筑、经验、总费用和终点目标。Boss 奖励后重新编译，消费授权贯穿门/道具/恢复策略；不能每层恢复初始血量或重新抽种子。

M3-B 按真实失败增加敌人阶段、大房地形、不可交换的道具机制和长期资源策略。优先减少不可恢复损伤、强制未知与误消费；安全条件下持续进攻，不能用消极绕行换取“存活时间”。不实现全部道具的笛卡尔积。

M3-C 增加 Mom 专属预警、攻击来源/身体部件、召唤和终点适配。所有状态映射从目标构建实际证据确认，不把通用速度外推称为 Boss 阶段预测。逐层独立结果用于定位失败，整局 Judge 仍要求连续性。

主线继续 Isaac。Eden 仅在武器替换/健康语义可靠后作为独立泛化集，记录初态和 Token；Tainted Eden 的受伤重构另列。随机性不能替代机制覆盖，也不能挑到好起点才开始统计。

## 5. 研究和费用边界

当前先验证各阶段可行性：本地检查优先，必要的正常实机与少量 DeepSeek 调用。统一报告非主动损失、资源毛支出、游戏时间、暂停、完整墙钟、回退与请求/token；未配置费率时费用为未知而不是零。

大样本稳定性、LLM/规则配对、技能消融和竞速研究暂缓。讨论人类顶尖速度时必须匹配版本、角色、路线、种子/辅助档位及计时；大量暂停后的游戏内速度不等于墙钟竞速优势。实验清单只在 README 维护。

建议实施分支分别为 codex/phase2-floor-controller、codex/phase2-skill-development、codex/phase3-mom-run；各阶段先交付可复现的最小链路，再按失败追加针对性工作。
