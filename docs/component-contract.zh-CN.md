# 战斗组件合同 v1

适用：M2-A 的可信本地组件。代码定义位于 `SocketBridge/python/combat/component_contracts.py`；七槽位与参数仍由 catalog 管理。此合同不提供任意代码隔离，模型程序必须等待 M2-B 的受限执行器。

## 能力与输入

能力声明明确 family、能否移动攻击、能否破坏普通障碍；未声明的可选能力默认不具备。组件只产生计算结果，不直接进行 IO、发按键、消费资源或改写传入快照。武器路由和逐帧观测为独立可选接口。

参数由目录边界检查，实际构筑与所需能力必须匹配。上下文包含 run、room visit、build revision、catalog revision；P2 补楼层实例到计划上下文。版本不匹配的结果不可执行。

## 输出与预算

`AttackProposal` 保留旧入口，增加可选 `ProposalContext`：观测帧、生效截止帧和版本。可信同步旧模块省略上下文时由宿主绑定当前调用；显式上下文必须匹配，异步模块不能靠省略身份绕过验证。

宿主限制每次攻击候选 1–16 个、路径最多 256 点、坐标绝对值不超过 100000 像素、攻击足迹宽度不超过 4096 像素、等待最多 90 游戏更新。分数与损害必须有限且有界；射击为中立或合法四向整数。目录可进一步收紧等待期限，不能放大宿主上限。

`hit_score` 是 0–1 启发式质量。旧 `expected_damage` 暂为伤害/更新帧估计，不代表已验证概率，P3 再统一预测时间窗与攻击收益。攻击足迹 v1 只表示线段及宽度，复杂形状暂不宣称支持。

## 生命周期与失败

逐帧观测钩子每个上下文/更新只推进一次；`propose` 在多个移动候选下重复调用，必须无动作提交副作用。实际执行确认与构筑事务将在 P2 之后的工作包接入，不能把预测动作当已执行。

模块状态至少绑定 run、room visit、build、catalog 与 profile。上下文变化重建实例，过期等待和旧提案无效。低血量可调整风险偏好，但必须保留兼容武器家族。

异常或非法结果记录组件、方法和原因并隔离该实例；普通泪弹可回退受信任普通泪弹实现。没有兼容发射器时明确停火、保留独立移动/避险并交给有界进展监督，不调用错误家族。输入释放及断线 TTL 始终由宿主和 Lua 执行；释放型武器可能因此攻击，不能宣称无风险。

该边界只约束已返回结果；可信 Python 的死循环仍可能阻塞。M2-B 未可信代码不得直接注册到控制线程。
