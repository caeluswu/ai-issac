# SocketBridge 控制可行性探针

本探针用于验证《以撒的结合：忏悔》原版中的状态采集、正常移动与射击、停止输入、超时释放、换房识别和断线后键盘接管。它不是自动通关程序。首次实机运行前，须从游戏日志确认版本为忏悔原版，而不是忏悔+，并使用隔离存档。

## 准备

1. 在隔离的忏悔原版环境中安装项目内的 `SocketBridge` 模组，按模组说明启用 `--luadebug`。Python 服务固定监听本机 `127.0.0.1:9527`。
2. 在一个无敌人的普通房间、靠近中央的位置开始。准备好测试结束后手动进入相邻房间。
3. 运行前关闭可能占用 `9527` 的其他 SocketBridge、Hub 或控制程序。不要在正式存档上执行本探针。

从 `D:\internship1\issac\SocketBridge\python` 运行：

```powershell
..\..\.venv\Scripts\python.exe -m apps.control_probe
```

程序最多等待游戏连接和玩家位置 60 秒。连接后确认 `FORCE_AI`，以 20 Hz 发送三轮右移、停止、向上射击、停止、左移加射击、停止。随后短暂右移并**完全停发动作**，检查 Lua 的 3 更新帧输入看门狗。最后恢复 `MANUAL`，留出 60 秒让你手动换房。服务断开后，程序请你确认键盘控制是否恢复；只有输入 `y`、`yes` 或 `是` 才计入验收通过。

若只需验证传感器能识别换房，可在开发测试时附加 `--room-command 'goto s.error.21'`。这会通过模组的控制台命令切换房间；它不能代替“经门走入相邻房间”的验收。

起始空房有右侧开门时，可附加 `--auto-door`。探针会读取门的坐标，先对准门，再用普通移动输入穿门；这是完整验收可接受的换房方式。`--auto-door` 与 `--room-command` 不能同时使用。

运行记录写在 `D:\internship1\issac\artifacts\control-mvp\`。每次运行有一份逐条 JSONL 和一份 `.summary.json`。完整通过需要所有动作阶段、静默看门狗、换房识别和键盘恢复均成功；非交互模式会把键盘确认留为待确认，整体不会标为通过。

## 判定与边界

- 位移阶段需在同一房间移动超过 20 像素；射击阶段需看到新的己方泪弹 ID。
- 停止阶段需在第 10 个游戏更新帧附近把速度降到 1.0 以下、末帧降到 0.1 以下，且末 5 次位置采样的位移不超过 5 像素。阈值依据首次实机轨迹修订：第 10 帧速度为 0.706，之后继续平滑衰减至约 0.02。静默看门狗还需先观察到超过 5 像素的主动位移。
- 如果游戏暂停、位置数据过期、换房发生在动作阶段、TCP 断开或命令模式未得到游戏确认，探针中止动作并记录失败。程序退出时会尝试发送零动作和 `MANUAL`；若链路已断，Lua 模组自身负责释放输入。
- 泪弹 ID 和位移都是观测证据；模拟 TCP 测试只能证明 Python 端协议与报告逻辑，**不能证明游戏实际接受了输入**。Lua 看门狗、游戏版本兼容性和键盘恢复必须实机复核。

## 离线测试

从 `SocketBridge\python` 运行：

```powershell
..\..\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

测试中的模拟游戏客户端只连接本机 TCP，不会启动或修改游戏。若本地执行环境禁止回环网络，需允许本机回环连接后再运行端到端测试。
