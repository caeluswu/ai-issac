# 第一阶段实机验收：自动启动、出门与首房清理

验收日期：2026-10-26。实现提交：`72ab465`，分支：`codex/phase1-auto-start`。

## 1. 结论与范围

第一阶段“从初始房间正常出门，经 DeepSeek 配置组件后清理首个战斗房”的工程目标通过。最终代码在十个封存种子的开发回归中完成 10/10 次完整 LLM 清房，没有规划降级；同代码、同存档基线、同种子的规则上层对照完成 9/10 次。

这十个种子用于开发与故障复现，不是独立留出集。重复回放不增加独立样本数。本结果不证明单房稳定胜率、整层能力、人类竞速水平或 SOTA。

## 2. 固定条件

- 游戏：Windows，Repentance 原版 `1.7.9b.J835`；可执行文件及模组哈希见 `configs/task/progression.yaml` 和各次 manifest。
- 角色：Isaac，普通难度，第一层正常初始房间；保留初始 D6，全程只使用移动和普通泪弹。
- 存档：项目方确认的全解锁槽 1；受保护副本由 `configs/task/save-baseline.slot-1.json` 定位。持久存档 SHA-256 为 `0477CE1F84B1C127E440B2B1FFE2E23D580D7D30C4F208AED79966EEBFC8A3A1`。每次恢复前后校验哈希；全解锁内容依据项目方声明，无自动成就核验。
- 模型：`deepseek-flash`。入房先完成分析、再输出组件与参数；战中按事件异步重规划。
- 窗口：`Fullscreen=0`、`PauseOnFocusLost=0`；原生暂停和菜单按键短暂激活游戏，普通控制允许后台执行。
- 初始化：仅在测量任务开始前设置种子、清除特殊种子效果并重启为 Isaac；战斗中不使用控制台杀敌、改血或改伤害。

随机种子由操作系统随机数生成器抽取十个不重复的非零 uint32，通过游戏 `Seeds.Seed2String` 转换，在第一场战斗前保存完整清单与哈希。清单哈希为 `8017d7689c153058c39a5659aa354797fc0f2c201f06e3fe667dd33acd7ef2bf`。

最终 LLM 与规则组各十次的代码哈希、Git 提交、实际种子和恢复的基线均逐对一致。每次由正常移动穿门，未读取下一房间敌人信息。十例共观察到 51 个敌方 NPC 实例、14 种类型/变体组合；范围限于本批第一层首个战斗房。

会话墙钟从控制会话创建计至清理完成，包含启动与暂停。Python 进程退出时可能继续等待已发出的 HTTP 工作线程回收，这段尾部等待不计入 `wall_seconds`；此表不是命令进程全耗时测量。

LLM 组平均游戏战斗时间较短、失血较少，但暂停推理使控制会话的墙钟时间更长。当前实现尚不能支持“平均实际通关速度优于顶尖人类”的判断。该小样本也不足以建立 LLM 相对规则的统计优势。

## 5. 失败与限制

规则样本 6（`HG96 6KF9`）保留为 `COMBAT_TIMEOUT`：120 游戏秒后仍有两只类型 12 的敌人，玩家无伤。日志末段移动与射击均为零，命中评分为零；岩石遮挡下的默认站位与路径评分形成无输出的局部停滞。下一批组件应优先改进射击通道导航和对零输出停滞的本地恢复。该失败未从统计中排除。

开发探索批次包含一次模型 JSON 修复失败后本地清房；它计为物理清房，未计为完整 LLM 成功。还保留了无敌环境实体造成假超时、短提前量配置限制射程，以及一次窗口激活失败的回归记录。最终实现区分 `CanShutDoors` 与环境威胁，提前量只限制敌人预测，随机初始化显式清除旧自定义种子，并在激活失败时安全停止。

敌人机制、移动继承、有效射程与危险范围仍使用有标记的近似，尚无逐怪精确仿真。需要在新的留出种子和更广房间分布上继续评测；M1 的高胜率门槛、整层与长途通关均不属于本次通过结论。
